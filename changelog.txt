CHANGELOG
=========

v1.0.5 (2026-09-18)

- Changed: Watchdog migrated from systemd user-unit to integrated Kodi service thread
- Changed: Legacy vpn-watchdog.service is stopped and removed automatically on upgrade
- Added: Watchdog activity visible in kodi.log with self-healing loop
- Added: Session gate prevents helper spawns on boot without active session
- Added: Connector lock logging reduced to once-per-event (no more spam)
- Added: Helper subprocess logging to standalone_wm.log with timestamp and PID
- Added: Log rotation on Kodi restart (standalone_wm.log → .old)
- Added: TUNNELLING toast shown during silent reconnect attempts
- Improved: Service resolver speed from 7s to under 30ms via prefix filtering and exact-match fast-path
- Improved: IPv6 management now targets only physical adapters, cutting disconnect time from 7s to under 1s and full location switches from 16s to under 3s

v1.0.4 (2026-09-17)

- Added: Cooldown functionality for rapid reconnection attempts (vpn_core.py)
- Added: Silent gate mechanism to reduce log noise during normal operations (vpn_core_upd.py)  
- Changed: Softened ICMP probe handling with fallback for unavailable endpoints (vpn_utils.py)
- Fixed: Session state preservation across crash/restart scenarios
- Fixed: End-to-end recovery flow verification (dead link → reconnect in under 1s)
- Improved: Watchdog coordination with SHIELD disconnect flags
- Improved: Manual session state persistence during emergency recovery

v1.0.3 (2026-09-15)

- Fixed: manual VPN sessions now survive Kodi restarts, crashes and automatic tunnel recovery.
  A session started manually stays manual until the user or the cycle-fail breaker ends it.
- Fixed: auto_connect on startup re-registers the session as manual, so it is no longer
  disconnected by the home timeout after ~13 seconds.
- Fixed: silent recovery and internal reconnect attempts no longer wipe the manual session state.
- Added: reconnect-failure dialog with a "Retry now" option (shown once per outage episode).
- Added: notification when repeated failures trip the cycle-fail breaker and auto-recovery stops.
- Added: failure dialogs are reset on manual connections and verified recovery.
- Fixed: metadata verification no longer produces false negatives on fresh tunnels - DNS
  readiness is awaited before probing metadata providers, killing the 2-second cold-start penalty.
- Added: per-provider diagnostics for metadata probe failures (return code and curl error detail).
- Improved: tunnel health checks log interface discovery, ping results and breaker state
  for faster field diagnosis.
- Fixed: tunnel report lines no longer claim a reconnect was not completed after a successful retry.
- Fixed: home timeout no longer removes the persistent manual session file.

v1.0.2 (2026-09-13)

- Added progress dialog with percentage display during custom profile bulk import
- Custom import can now be cancelled mid-run (Cancel button stops further imports cleanly)
- Prevent duplicate FriendlyName headers when source config already contains one
- Drastically faster post-connect metadata verification (single ping probe, tighter curl timeouts, no retry delays)
- DNS leak test now shows a progress dialog and refuses to run while the firewall killswitch is active
- Fixed custom profiles not claiming the default route (ip4-auto-default-route now enabled, matching Mullvad behavior)

v1.0.1 (2026-09-12)

- Initial dedicated release for Linux Desktop and Debian/LMDE architectures. This is the first release of the addon built specifically for Linux Desktop environments, branching away from the embedded LibreELEC target.
- Structural migration from legacy ConnMan engine over to native NetworkManager (nmcli) configuration. All tunnel bring-up, teardown and profile management now goes through nmcli, removing the ConnMan dependency entirely.
- Converted provider blueprint routines to output generic WireGuard .conf profile schemas. Provider templates (NordVPN, PIA, Custom) now emit standard WireGuard configuration files that can be imported by any compatible tool.
- Shifted systemd watchdog services to unprivileged user-space systemd execution loops. The watchdog now runs as a plain user unit without root requirements, making it safer on multi-user desktop systems.
- Replaced hardcoded physical network device references with global dynamic interface sniffing utilities. Network devices are now discovered at runtime instead of being pinned to fixed interface names like enp3s0 or wlp2s0.
